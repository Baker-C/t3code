# Battle detail page

T3 battle: `926dc291-4aa0-4703-b138-04b60e11933d` (project `t3code`, slug from "Battle upgrades: battle page").

## Objective

When the user clicks a battle in the sidebar, the main window (the router `Outlet` area where threads usually show) shows a battle page with:

1. Battle title (+ phase, defeated timestamp when applicable)
2. Battle description — the existing `goal` field (`OrchestrationBattle.goal`, the battle's only free-text field)
3. Battle goals — the existing victory conditions (`OrchestrationBattle.victoryConditions`), with state and scope progress
4. The list of threads enlisted in the battle; click a thread to open it

## Constraints and facts (from codebase audit 2026-08-23)

- No server or schema change is necessary. The shell subscription already streams full battles (`OrchestrationShellSnapshot.battles`, `contracts/orchestration.ts:589`) and threads carry `battleId` (`orchestration.ts:531`). Membership = `thread.battleId === battle.id && thread.environmentId === battle.environmentId` (pattern: `BattleBreadcrumbItem.tsx:76-80`).
- Existing hooks: `useBattle(environmentId, battleId)` (`apps/web/src/state/battles.ts:56-64`), `useThreadShells()` (`apps/web/src/state/entities.ts:119-121`). Live updates come for free via the shell reducer.
- Routing is TanStack Router, file-based (`apps/web/src/routes/`). `routeTree.gen.ts` is regenerated by `@tanstack/router-plugin` during `vp dev`/`vp build`.
- Page precedents: `routes/usage.tsx` + `components/usage/UsagePage.tsx` (simple), `routes/_chat.pull-requests.tsx` (in-`_chat` non-thread page). Layout primitives: `SidebarInset`, `WorkspacePageHeader`, `WorkspaceBreadcrumb`, `WorkspacePageContainer`.
- Today, clicking a sidebar battle row only toggles collapse (`Sidebar.tsx:1962,1998`). Hover actions (new thread, reopen) already stop propagation.

## Changes

1. **New route** `apps/web/src/routes/_chat.battles.$environmentId.$battleId.tsx`
   - `createFileRoute("/_chat/battles/$environmentId/$battleId")` — inherits the `_chat` auth gate and shortcuts.
   - Thin route file; page body in `apps/web/src/components/battle/BattlePage.tsx` (UsagePage pattern).
2. **BattlePage component**
   - Data: `useBattle`, `useThreadShells` filtered to the battle; helpers `battleScopeProgress`, `resolveBattlePhase` from `@t3tools/client-runtime`.
   - Layout: `SidebarInset` → `WorkspacePageHeader` with breadcrumb (battle title) → scrollable `WorkspacePageContainer`.
   - Sections: header (title, phase, dates) → goal text → victory conditions list (state badge, size score, strike reason for descoped) → thread list (navigate to `/$environmentId/$threadId` on click; show archived state).
   - Not-found state when the battle id does not resolve (deleted battle or disconnected environment).
3. **Sidebar navigation** (`apps/web/src/components/Sidebar.tsx`)
   - Battle row click → `router.navigate` to the battle page.
   - The chevron keeps the collapse behavior (own click target, stops propagation).
4. **Route tree** — regenerate `routeTree.gen.ts` via the router plugin.
5. **Docs** — add the battle page to `docs/user/battles.md`.

## Non-goals

- No new `description` field or command — `goal` is the description surface. (Follow-up candidate: edit `goal` from the page via `battle.meta.update`, which already supports it end-to-end.)
- No server query for threads-by-battle (client already has all threads).
- No mobile surface (mobile has zero battle support today).
- No changes to LegacySidebar (feature-flagged, has no battle support).
